01 — Rappel enum de base

📌 Qu'est-ce qu'un enum ?

Un enum est un type spécial dont les valeurs possibles sont des constantes nommées et prédéfinies. En Java, c'est implicitement une sous-classe de java.lang.Enum.

java enum basique 
public enum Jour {
    LUNDI, MARDI, MERCREDI, JEUDI, VENDREDI, SAMEDI, DIMANCHE;
}

// Utilisation
Jour j = Jour.LUNDI;
System.out.println(j.name());    // "LUNDI"
System.out.println(j.ordinal()); // 0
Jour[] jours = Jour.values();      // tous les membres
Jour k = Jour.valueOf("MARDI");  // Jour.MARDI
02 — Champs et constructeur

⚙️ Principe

On peut ajouter des champs à un enum. Chaque constante appelle alors le constructeur (toujours private) en passant ses valeurs entre parenthèses.

java Planète avec masse et rayon 
public enum Planete {
    MERCURE(3.303e+23, 2.4397e6),
    VENUS  (4.869e+24, 6.0518e6),
    TERRE  (5.976e+24, 6.37814e6),
    MARS   (6.421e+23, 3.3972e6);

    private final double masse;   // en kg
    private final double rayon;  // en m

    // Constructeur OBLIGATOIREMENT private
    Planete(double masse, double rayon) {
        this.masse  = masse;
        this.rayon  = rayon;
    }

    public double getMasse()  { return masse; }
    public double getRayon()  { return rayon; }

    static final double G = 6.67300E-11;

    public double gravite() {
        return G * masse / (rayon * rayon);
    }
}

// Utilisation
System.out.println(Planete.MARS.gravite()); // 3.71 m/s²
⚠ Règle : Le constructeur d'un enum est toujours private (ou package-private implicitement). Il est interdit de le déclarer public ou protected.
03 — Méthode abstraite par constante

🔀 Corps de méthode spécifique à chaque constante

On peut déclarer une méthode abstract dans l'enum et la redéfinir pour chaque constante. Chaque constante devient ainsi une classe anonyme interne.

java Opération arithmétique 
public enum Operation {
    PLUS("+") {
        public double appliquer(double x, double y) { return x + y; }
    },
    MOINS("-") {
        public double appliquer(double x, double y) { return x - y; }
    },
    FOIS("*") {
        public double appliquer(double x, double y) { return x * y; }
    },
    DIVISE("/") {
        public double appliquer(double x, double y) { return x / y; }
    };

    private final String symbole;

    Operation(String symbole) { this.symbole = symbole; }

    public abstract double appliquer(double x, double y);

    public String toString() { return symbole; }
}

// Utilisation
for (Operation op : Operation.values())
    System.out.printf("5 %s 3 = %.1f%n", op, op.appliquer(5, 3));
04 — Implémenter une interface

🔌 Un enum peut implémenter des interfaces

C'est utile pour utiliser l'enum de façon polymorphique. L'enum ne peut pas extends une classe (il hérite déjà de Enum), mais il peut implements plusieurs interfaces.

java Enum + interface 
public interface Affichable {
    String afficher();
}

public enum Couleur implements Affichable {
    ROUGE("#FF0000"),
    VERT ("#00FF00"),
    BLEU ("#0000FF");

    private final String hex;

    Couleur(String hex) { this.hex = hex; }

    @Override
    public String afficher() {
        return name() + " → " + hex;
    }
}

// Polymorphisme possible
Affichable a = Couleur.ROUGE;
System.out.println(a.afficher()); // ROUGE → #FF0000
05 — EnumMap & EnumSet

🗺 EnumMap

  • Map spécialisée avec des clés de type enum
  • Plus performante que HashMap
  • Itération dans l'ordre de déclaration
EnumMap<Jour, String> agenda
    = new EnumMap<>(Jour.class);
agenda.put(Jour.LUNDI, "Réunion");

🧩 EnumSet

  • Set ultra-rapide stocké en bitmap
  • Seuls les éléments d'un même enum
  • Factory methods : of(), allOf(), range()
EnumSet<Jour> weekend =
    EnumSet.of(Jour.SAMEDI, Jour.DIMANCHE);

EnumSet<Jour> semaine =
    EnumSet.range(Jour.LUNDI, Jour.VENDREDI);
06 — Méthodes utiles héritées
Méthode Type retour Description
name() String Nom exact de la constante (identique à toString() par défaut)
ordinal() int Position dans la déclaration (commence à 0) — à éviter pour la logique métier
values() T[] Tableau de toutes les constantes dans l'ordre de déclaration
valueOf(String) T Retourne la constante dont le nom correspond (lève IllegalArgumentException si introuvable)
compareTo(T) int Compare par ordinal
getDeclaringClass() Class<E> Retourne la classe de l'enum (utile avec les méthodes abstraites)
07 — Pattern Strategy avec enum

💡 Enum comme strategy embarquée

Plutôt qu'une hiérarchie de classes, on peut regrouper toutes les variantes dans un seul enum avec une méthode abstraite. Plus compact, toujours type-safe.

java Strategy — calcul de remise 
public enum TypeClient {
    STANDARD {
        public double remise(double prix) { return prix; }
    },
    PREMIUM {
        public double remise(double prix) { return prix * 0.9; }
    },
    VIP {
        public double remise(double prix) { return prix * 0.75; }
    };

    public abstract double remise(double prix);
}

// Utilisation
TypeClient tc = TypeClient.VIP;
System.out.printf("Prix final : %.2f€%n", tc.remise(100.0));
// Prix final : 75.00€
08 — Singleton via enum

🔒 L'enum est le seul singleton vraiment thread-safe

Joshua Bloch (Effective Java) recommande l'enum pour implémenter un Singleton : la JVM garantit qu'une seule instance existe, même en cas de désérialisation ou de réflexion.

❌ Singleton classique (fragile)
public class Config {
  private static Config instance;
  private Config() {}
  public static Config get() {
    if (instance == null)
      instance = new Config();
    return instance;
  }
}
✅ Singleton enum (robuste)
public enum Config {
  INSTANCE;

  private String host = "localhost";

  public String getHost() {
    return host;
  }
}

// Config.INSTANCE.getHost()
09 — Règles & pièges à éviter

✅ À faire

  • Toujours déclarer les champs final
  • Préférer EnumMap / EnumSet aux collections génériques
  • Surcharger toString() pour l'affichage métier
  • Utiliser switch sur les enums (exhaustif)

❌ À éviter

  • Utiliser ordinal() pour la logique métier (fragile)
  • Modifier un champ non-final (anti-pattern)
  • Créer des enums avec trop de responsabilités
  • Oublier le constructeur private
💡 Astuce : Pour retrouver une constante depuis une valeur métier (ex. un code), ajoutez une méthode static fromCode(int code) avec une Map statique pour éviter de parcourir values() à chaque appel.
java Recherche optimisée par code 
public enum CodeErreur {
    OK(200), NOT_FOUND(404), SERVER_ERROR(500);

    private final int code;

    CodeErreur(int code) { this.code = code; }

    private static final Map<Integer, CodeErreur> MAP =
        Arrays.stream(values())
              .collect(Collectors.toMap(e -> e.code, e -> e));

    public static CodeErreur fromCode(int code) {
        return MAP.getOrDefault(code, SERVER_ERROR);
    }
}

// CodeErreur.fromCode(404) → NOT_FOUND
10 — Récapitulatif visuel
java Structure complète d'un enum enrichi 
public enum MonEnum implements UneInterface {

    // 1. Constantes avec arguments du constructeur
    CONSTANTE_A(arg1, arg2) {
        public String methodeAbstraite() { return "A"; }
    },
    CONSTANTE_B(arg1, arg2) {
        public String methodeAbstraite() { return "B"; }
    };

    // 2. Champs (toujours final de préférence)
    private final Type1 champ1;
    private final Type2 champ2;

    // 3. Constructeur private
    MonEnum(Type1 c1, Type2 c2) {
        this.champ1 = c1;
        this.champ2 = c2;
    }

    // 4. Méthodes concrètes partagées
    public Type1 getChamp1() { return champ1; }

    // 5. Méthode abstraite (implémentée par chaque constante)
    public abstract String methodeAbstraite();

    // 6. Méthode statique utilitaire
    public static MonEnum fromChamp1(Type1 v) { ... }

    // 7. toString optionnel
    @Override
    public String toString() { return champ1.toString(); }
}
